# Plan-Act-Reflect 思考模式（动态、带反思、可修正）

> Plan-and-Execute 是静态一次性规划；Plan-Act-Reflect 是动态迭代、能自我修正的增强版。

## 流程

```
Plan（规划）→ Act（执行一步）→ Reflect（反思）→ Plan（修订）→ Act → Reflect → ... → 完成
```

- **Plan**：制定/修订计划，决定本步要做什么
- **Act**：执行当前一步（含工具调用）
- **Reflect**：评估执行结果，决定：是否调整计划？是否重跑？下一步策略？

## 各阶段职责与输出格式

### 1. Plan（Step1 - 任务分析节点）

**职责**：
- 首次：根据用户需求做初步规划
- 后续轮次：接收 Reflect 反馈，修订计划
- 输出：下一步策略、完成度、任务状态

**输入**：用户需求、执行历史、当前任务、**Reflect 反馈（若有）**

**输出格式**：
```
任务状态分析: [当前任务完成情况分析]
执行历史评估: [对已完成工作的评估]
下一步策略: [具体执行计划和策略，若有 Reflect 反馈则体现修订]
完成度评估: [0-100]%
任务状态: [CONTINUE/COMPLETED]
```

---

### 2. Act（Step2 - 精准执行节点）

**职责**：
- 按 Plan 的策略执行当前一步
- 使用工具完成具体操作
- 记录执行过程与结果

**输入**：用户需求、Plan 的下一步策略

**输出格式**：
```
执行目标: [本轮要执行的目标]
执行过程: [执行步骤和使用的工具]
执行结果: [具体结果和获得的信息]
质量检查: [对执行结果的质量评估]
```

---

### 3. Reflect（Step3 - 质量监督节点）

**职责**：
- 评估 Act 的结果是否符合预期
- 决定：通过 / 需重跑 / 需优化
- 输出供下一轮 Plan 使用的反馈：计划修订建议、下一步决策

**输入**：用户需求、Act 的执行结果

**输出格式**：
```
质量评估: [对执行结果的详细质量评估]
问题识别: [发现的问题和不足]
改进建议: [具体的改进建议]
计划修订建议: [供下一轮 Plan 参考的修订方向，如：重跑本步、调整策略、补充某环节等]
质量评分: [0-100]分
是否通过: [PASS/FAIL/OPTIMIZE]
下一步决策: [CONTINUE_AND_REVISE/REEXECUTE_CURRENT/COMPLETE]
```

**下一步决策说明**：
- `CONTINUE_AND_REVISE`：通过或可优化，进入下一轮 Plan（可带修订建议）
- `REEXECUTE_CURRENT`：本步需重跑，下一轮 Plan 应修订策略后让 Act 重做
- `COMPLETE`：任务已完成

> 若 DB 中 QUALITY_SUPERVISOR 的 prompt 尚未包含「计划修订建议」「下一步决策」，可先沿用原有格式；代码会兼容解析，缺失时按「是否通过」决策。

**Reflect prompt 升级示例（可选）**：在原有输出格式后追加：
```
计划修订建议: [供下一轮 Plan 参考的修订方向]
下一步决策: [CONTINUE_AND_REVISE/REEXECUTE_CURRENT/COMPLETE]
```

---

### 4. Summary（Step4 - 执行总结节点）

**职责**：汇总执行过程，生成面向用户的最终答案。

---

## 与 Plan-and-Execute 的对比

| 维度       | Plan-and-Execute        | Plan-Act-Reflect                    |
|------------|-------------------------|-------------------------------------|
| 规划       | 事前一次性列出所有步骤  | 动态、可修订                         |
| 执行中修正 | 不修正                  | 根据 Reflect 反馈修正计划           |
| 错误处理   | 不回头                  | 可重跑、可调整                       |
| 复杂度     | 适合简单任务            | 适合复杂任务、未知情况、深度思考     |
