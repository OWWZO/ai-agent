# Quickstart: 后端事实对话账本重构验收

## 1. 前置准备

1. 清理旧历史数据，确保本次只验证新模型写入的数据。
2. 应用最新 `schema.sql` 或对应 DDL 变更，确认 `ai_agent_message.generated_files_json` 已存在。
3. 启动后端与前端。

## 2. 验证历史详情与实时结束态一致

1. 新建一条 `PLAN_SOLVE` 会话。
2. 发送会生成结构化过程和文件结果的问题。
3. 记录对话结束时：
   - 最终回答
   - 左侧可见的关键过程块
   - 右侧可见的文件入口
4. 刷新页面并重新打开该会话。
5. 确认历史详情复现相同的最终可见结果。

**期望结果**

- 历史详情与实时结束态一致
- 没有出现另一套 history-only 布局

## 3. 验证生成文件直接从消息账本可查

1. 完成一条会生成 HTML/Markdown/PPT 或文件的会话。
2. 查询该轮对应的 `ai_agent_message.generated_files_json`。
3. 对照前端历史详情里的文件入口。

**期望结果**

- `generated_files_json` 能直接列出本轮生成文件摘要
- 不需要解析 `ai_agent_message_event.payload_json` 才知道本轮生成了哪些文件

## 4. 验证续聊记忆来自后端事实账本

1. 在同一会话中先完成一轮包含工具调用和文件产物的任务。
2. 再发送“继续刚才任务”或“基于刚才生成的文件继续补充”。
3. 观察下一轮的行为与输出。

**期望结果**

- 系统能感知上一轮工具事实与生成文件
- 不会只剩“问题 + 最终回答”的记忆

## 5. 验证错误/强停场景

1. 构造一条会在中途报错或被强制停止的结构化会话。
2. 打开历史详情。

**期望结果**

- 已经产生的事实块仍可见
- 终态为 `error` 或 `force_stop`
- 若存在文件引用缺失，前端能看到明确缺失原因

## 6. 自动化回归

运行：

```bash
mvn test -pl ai-agent-station-study-app -DskipTests=false
cd ui && npm run lint
cd ui && npm run build
```

重点关注：

- 历史持久化测试
- 历史详情接口测试
- 会话记忆恢复测试
- 生成文件摘要提取测试
