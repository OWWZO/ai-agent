# Feature Specification: 对话历史最终态重构与一致性修复

**Feature Branch**: `[005-fix-history-replay]`  
**Created**: 2026-04-16  
**Status**: Draft  
**Input**: User description: "修正当前 005 需求理解偏差：历史重开后不能只剩“搜索完成 / 总结完成 / 最终总结回复”这类最小摘要，而必须按对话结束时界面最终可见的细节态 1:1 展示，包括思考过程、任务计划、工具调用、搜索/总结卡片和最终产物；不要求逐 token 回放，但要求用户几天后回来仍能看到结束时那份完整对话细节"

## Existing System Context *(mandatory for brownfield features)*

- **Affected Modules**: `ui`、`ai-agent-station-study-domain`、`ai-agent-station-study-infrastructure`、`ai-agent-station-study-trigger`、`ai-agent-station-study-app`
- **Existing Capabilities to Reuse**: 现有会话列表与详情接口、按轮次组织的历史消息模型、最终答案展示能力、工作区文件预览面板、稳定文件资源引用能力
- **Out of Scope**: 不保留历史逐 token 或逐增量实时回放能力、不新增独立历史播放器、不重做在线流式协议、不改造无关的聊天或数据分析主流程、不为开发阶段的临时脏数据提供长期兼容方案
- **Current Constraints**: 当前历史实现把“最终态”错误收缩成少量摘要事件，导致重新打开历史时看不到对话结束时真实仍可见的思考过程与工具调用细节；重新打开历史时必须以已持久化最终界面态为准；用户几天后回看同一段对话时，应看到与对话结束时一致的最终细节块顺序、数量和内容；历史工作区内容只能依赖稳定持久化引用，不能依赖运行时临时路径；深度研究现有正确历史展示行为不能被破坏；三张历史表需要同步做字段属性收敛与结构重构

## Clarifications

### Session 2026-04-16

- Q: “历史最终态细节”具体指什么？ → A: 指对话结束时界面上最终仍可见的完整细节态，需 1:1 保留思考过程、计划、任务分组、工具调用、搜索/总结卡片和最终结果，而不是只保留摘要
- Q: 是否要求历史继续保留执行过程中的每个流式增量？ → A: 不要求逐 token/逐增量回放，但凡是在对话结束时界面上仍可见的思考文本或工具调用细节，都必须在历史中完整保留
- Q: `ai_agent_message_event` 这张表以后应承担什么历史语义？ → A: `ai_agent_message_event` 继续作为历史细节主表，但存储的是最终界面可见细节单元，而不是最小摘要或全过程增量
- Q: `ai_agent_message_event` 中最终态细节事件的记录粒度应是什么？ → A: 一条最终界面可见细节单元对应一条 `ai_agent_message_event` 记录，不能把多个最终卡片合并成一条摘要
- Q: 当同一份最终细节既出现在对话区，又关联到工作区时，历史模型应如何定义 1:1？ → A: 同一最终细节只保留一份 canonical 记录，并记录其展示区域或关联产物；历史渲染时同时恢复对话区和工作区关系
- Q: “1:1 最终细节历史模型”这次的正式适用范围是什么？ → A: 覆盖 `PLAN_SOLVE` 和 `REACT`；普通 `CHAT` 继续保持轻量历史模型
- Q: 旧历史数据的处理策略应是什么？ → A: 不兼容旧历史数据可直接删除，不做双路径兼容
- Q: `ai_agent_message` 的职责边界应是什么？ → A: `ai_agent_message` 保留最终答案、状态、指标和摘要，最终细节全部放到 `ai_agent_message_event`
- Q: `ai_agent_conversation` 的职责边界应是什么？ → A: `ai_agent_conversation` 只保留归属、标题、模式、排序、预览、计数等轻量摘要字段

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 延迟回看仍能看到 1:1 最终对话细节 (Priority: P1)

作为重新查看历史会话的用户，我希望在刷新页面、重新登录或过几天后再打开同一段对话时，仍能看到当时对话结束时界面上那份完整的最终细节态，包括思考过程、任务分组、工具调用、搜索/总结卡片、最终答案和最终结果展示，而不是只剩几条摘要。

**Why this priority**: 这是历史能力的核心价值。用户回看历史不是为了看“系统总结”，而是为了重新获得结束时那份完整可读的对话细节上下文。

**Independent Test**: 完成一条深度思考会话，记录其结束时界面上的思考面板、任务分组、工具调用卡片、搜索/总结卡片、最终答案和工作区产物的数量、顺序与文本内容；刷新页面或延迟重新打开该会话，确认历史详情与该最终界面态一致。

**Acceptance Scenarios**:

1. **Given** 一条对话已经执行完成并展示了思考面板、多个工具调用卡片和最终答案，**When** 用户刷新页面或延迟重新打开该会话，**Then** 历史详情必须展示相同数量、相同顺序且文本内容一致的最终细节块
2. **Given** 一条对话在执行过程中产生过大量流式思考与工具增量，**When** 用户重新打开历史会话，**Then** 系统不要求逐条回放这些增量，但凡结束时界面仍可见的思考文本和工具调用细节都必须完整保留

---

### User Story 2 - 正确展示最终计划状态 (Priority: P2)

作为查看历史会话的用户，我希望如果某些计划步骤在对话结束时已经完成，那么重新打开历史时仍然看到它们在最终界面中的完成态，并且它们仍位于正确的对话细节位置，而不是退回成一开始的计划组件。

**Why this priority**: 计划状态是最终结果的一部分。若历史重新打开后计划组件回退，用户会误判这轮执行并未真正完成。

**Independent Test**: 完成一条包含计划步骤推进与完成状态更新的深度思考会话，等待其最终完成后刷新页面并重新打开历史详情，确认所有已完成步骤仍展示为已完成，且不被压缩成单条“计划完成”摘要。

**Acceptance Scenarios**:

1. **Given** 一条深度思考会话中的多个计划步骤在结束时已经显示为已完成，**When** 用户重新打开该会话，**Then** 每个步骤都必须继续显示为已完成状态
2. **Given** 历史详情中同时存在初始计划信息和后续完成状态，**When** 系统渲染历史展示，**Then** 页面必须以最终计划状态为准，不能退化为只剩一条计划摘要或回退为初始计划组件

---

### User Story 3 - 可复看最终工作区产物 (Priority: P3)

作为查看历史工作区产物的用户，我希望在对话结束后重新打开会话时，仍能点击并查看最终留下的文件或其他工作区结果；若资源已不可读取，也应看到明确原因，而不是通用报错，同时不能因为细节展示被过度压缩而找不到这些产物入口。

**Why this priority**: 工作区产物往往是对话的最终输出之一。若历史里这些产物无法再次打开，用户就无法真正复用过去的对话成果。

**Independent Test**: 完成一条会生成工作区文件的对话，等待其执行完成后刷新页面并重新打开该会话，点击工作区文件，确认可正常预览；若资源失效，确认页面展示明确不可用原因。

**Acceptance Scenarios**:

1. **Given** 一条已完成会话在结束时展示了可点击的工作区文件或结果，**When** 用户重新打开历史会话并点击该结果，**Then** 系统必须成功展示其内容
2. **Given** 某个历史工作区结果的引用目标已失效或不可读取，**When** 用户点击该结果，**Then** 页面必须展示明确的不可用状态，而不是只显示通用加载失败

---

### Edge Cases

- 对话执行过程中出现过、但在对话结束前已从界面上被替换或消失的瞬时增量，不要求按原增量轨迹回放
- 同一轮对话中若最终界面展示了多个同类型工具细节，它们在历史中仍必须作为多个最终细节块保留下来，不能被错误折叠成一个
- 若思考文本在执行过程中持续流式追加，但结束时界面只展示一份完整思考面板，历史中必须保留这份完整思考面板，而不是只保留“思考完成”提示
- 若某个工具调用最终以失败、取消或部分完成状态留在界面上，历史中也必须以对应最终状态展示该工具调用细节
- 计划步骤在会话临近结束时才更新为完成状态时，历史详情仍必须以最终状态为准
- 历史详情中既包含初始计划信息，也包含执行后的计划完成结果时，系统必须避免把两者混淆成同一种展示状态
- 若最终答案、思考过程和工具调用在结束时同时可见，历史重新打开后不能只剩最终答案
- 历史工作区文件或结果的引用目标不存在、过期或不可访问时，用户仍必须看到可理解的失败原因
- 深度研究模式当前已能正确展示最终结果的历史行为不能因为本次重构出现状态回退、结果缺失或细节丢失

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每一轮已完成对话持久化一份可直接用于历史详情展示的最终界面细节态，而不是在读取历史时把若干最小摘要临时拼成替代视图
- **FR-002**: 系统 MUST 在重新打开历史会话时，展示与对话结束时一致的最终细节块集合，包括思考过程、任务计划、任务分组、工具调用、搜索/总结卡片、最终答案和最终工作区产物
- **FR-003**: 系统 MUST 保持历史细节块与对话结束时界面可见细节的 1:1 对应关系，确保数量、顺序、标题、状态和摘要文本不被随意压缩
- **FR-003A**: 系统 MUST 为同一份同时出现在对话区和工作区的最终细节维护单一 canonical 记录，并通过展示区域或关联引用恢复其跨区域展示关系，不能为同一内容持久化两份互相独立的真相源
- **FR-004**: 系统 MUST 明确区分“执行中的瞬时流式增量”和“对话结束时仍可见的最终细节块”；前者不要求逐增量回放，后者必须长期保留
- **FR-005**: 系统 MUST 让凡是在对话结束时仍可见的思考文本块，在历史中以完整最终文本重新展示，而不是只显示“思考完成”之类的占位说明
- **FR-006**: 系统 MUST 让凡是在对话结束时仍可见的工具调用块，在历史中继续展示其工具名称、执行状态和用户可读摘要，而不是退化成“搜索完成”或“工具完成”这类通用提示
- **FR-007**: 系统 MUST 支持同一轮对话保留多个同类型的最终工具细节块，只要这些细节在对话结束时属于用户可见的最终结果，就不能被错误折叠为单项
- **FR-008**: 系统 MUST 保留每个计划步骤的最终生命周期状态，包括已完成状态，使重新打开历史后的展示结果与对话结束时一致
- **FR-009**: 系统 MUST 明确区分初始计划信息与最终计划状态，避免历史读取时把最终完成状态重新渲染为初始计划组件、单条摘要或其他弱化视图
- **FR-010**: 系统 MUST 让历史详情存在单一持久化真相源，避免多份语义重叠的存储结果在读取时互相覆盖、回退或冲突；历史细节主表由 `ai_agent_message_event` 承担
- **FR-011**: 系统 MUST 将历史列表所需的轻量摘要信息与历史详情所需的最终界面细节信息分离，避免为列表读取携带不必要的详细载荷
- **FR-012**: 系统 MUST 让 `ai_agent_conversation` 只承担会话归属、标题、模式、排序、预览和计数等轻量摘要职责，不再承载详情快照或细节字段
- **FR-013**: 系统 MUST 让 `ai_agent_message` 只承担单轮最终答案、执行状态、基础指标和必要摘要字段，不再承担最终细节明细存储职责
- **FR-014**: 系统 MUST 让历史工作区产物通过稳定且长期可解析的引用进行访问，而不是依赖只在执行当时有效的临时路径或运行时上下文
- **FR-015**: 系统 MUST 在历史工作区产物无法访问时返回明确的不可用状态和原因，而不是向用户暴露通用获取失败提示
- **FR-016**: 系统 MUST 将 1:1 最终细节历史模型正式应用到 `PLAN_SOLVE` 和 `REACT` 两类结构化细节模式，确保两者都按对话结束时最终界面细节进行历史恢复
- **FR-016A**: 系统 MUST 保持普通 `CHAT` 使用轻量历史模型，不因本次结构化细节改造而被强行迁移到同一套复杂历史细节模型
- **FR-016B**: 系统 MUST 在重构深度思考历史模型时，保持深度研究及其他未受影响模式的最终历史展示不发生可见回归
- **FR-017**: 系统 MUST 支持对同一条会话进行“对话结束时最终界面细节”和“刷新后或延迟重开后的历史细节”的对照验收，以验证最终态一致性
- **FR-018**: 系统 MUST 使新的历史持久化模型面向长期查看最终细节的场景扩展，而不是再次围绕完整实时回放能力堆叠冗余结构
- **FR-019**: 系统 MUST 将 `ai_agent_message_event` 从过程事件表收敛为最终界面细节事件表，历史详情默认只读取这些最终细节事件
- **FR-020**: 系统 MUST 让 `ai_agent_message_event` 中的一条记录对应一个最终界面可见细节单元，避免把多个最终卡片合并进单条记录后再由读取逻辑二次拆分
- **FR-021**: 系统 MUST 同步重构 `ai_agent_conversation`、`ai_agent_message`、`ai_agent_message_event` 三张历史表的字段职责、约束和默认值，删除仅服务于实时回放或已无业务价值的冗余设计
- **FR-022**: 系统 MUST 不要求为不兼容的新旧历史模型提供长期双路径兼容；若上线切换前已有旧历史数据，可直接删除后再启用新模型

### Key Entities *(include if feature involves data)*

- **Conversation Summary**: 面向历史列表的轻量会话摘要，只保留标题、模式、时间、预览和计数等必要信息
- **Conversation Turn**: 一轮用户请求及其最终完成结果，是历史详情的父级单元，只保留最终答案、状态、指标和必要摘要
- **Final Visible Detail Snapshot**: 对话结束时用户在界面上最终仍可见的完整细节集合，包含思考过程、计划、任务分组、工具调用、搜索/总结卡片、最终答案和最终结果产物
- **Reasoning Detail Block**: 最终态细节中的思考过程展示单元，用于承载对话结束时仍可见的完整思考文本
- **Tool Call Detail Block**: 最终态细节中的单个工具调用展示单元，需保留工具身份、状态和用户可读摘要，可与其他同类型细节并存
- **Plan Step Final State**: 某个计划步骤在对话结束时的最终可见状态，用于历史展示中区分初始计划与完成状态
- **Workspace Artifact Reference**: 指向历史工作区结果内容的稳定引用，用于支持延迟重开后的访问与预览
- **Final Detail Event**: 存放在 `ai_agent_message_event` 中的单个最终界面细节记录，只表达一个历史详情真正需要保留的最终可见细节单元，并可通过展示区域或关联引用关联到工作区产物

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在验收样本中，100% 的深度思考历史会话在刷新后或延迟重开时，都能展示与对话结束时一致的最终细节块数量、顺序和类型分布
- **SC-002**: 在验收样本中，100% 对话结束时仍可见的思考过程文本和工具调用卡片，在重新打开历史会话后继续完整可见，不退化成通用摘要提示
- **SC-003**: 在验收样本中，100% 已完成的计划步骤在重新打开历史会话后仍显示为已完成状态，不再回退成初始计划组件或摘要态
- **SC-004**: 对于结束时包含多个同类型最终工具细节块的历史会话，100% 的样本在重新打开后保留相同数量的最终细节块，不发生错误折叠
- **SC-005**: 对新生成且包含工作区文件或其他最终产物的历史会话，95% 以上的结果点击后可在首次尝试时成功预览；其余情况必须展示明确不可用状态，而不是通用 `Failed to fetch`
- **SC-006**: 深度研究历史展示回归样本继续保持最终结果和最终细节完整可见，不新增状态回退、结果缺失或细节丢失问题

## Assumptions

- 产品当前不再要求历史详情逐 token 或逐增量回放实时过程，但要求长期稳定保留对话结束时最终仍可见的细节态
- “最终态细节”指用户在一轮对话结束时仍能在界面上看到、并且对后续回看有价值的思考过程、计划、工具结果、搜索/总结卡片、答案和产物
- 若开发阶段已有临时测试数据与新模型不兼容，可在切换时清理，不以兼容这些中间态测试数据为本次验收目标
- 若旧历史数据与新模型不兼容，可在切换时直接删除，不以兼容旧模型数据为本次验收目标
- 会话列表与会话详情继续保持按需加载分层，不要求列表接口承担详情细节职责
- 历史工作区产物可复用现有稳定文件服务或等价持久化引用能力，不额外引入新的文件管理入口
- 深度思考是本次重构重点，深度研究作为回归保护对象，需要保持现有正确行为
- `PLAN_SOLVE` 和 `REACT` 都属于需要结构化最终细节历史的模式；普通 `CHAT` 在本次范围内继续保留轻量历史
- 本次需求与 `005-fix-history-replay` 属于同一特性范围，不拆分为新的独立 feature
- `ai_agent_message_event` 将继续保留，但语义调整为“历史最终界面细节表”，不再默认承载全过程增量事件或最小摘要替代视图
